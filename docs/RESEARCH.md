# 从对比学习到检索实验：CLIPScope 研究笔记

## 1. 优化目标决定了哪些能力被直接监督

设批次包含 N 对图文，图像编码器 f 与文本编码器 g 输出归一化表示 uᵢ、vⱼ。相似度矩阵为 Sᵢⱼ = uᵢᵀvⱼ / τ。CLIP 使用两个方向的交叉熵均值：

```math
L = -\frac{1}{2N}\sum_i\left[
\log\frac{\exp(S_{ii})}{\sum_j\exp(S_{ij})}
+\log\frac{\exp(S_{ii})}{\sum_j\exp(S_{ji})}\right].
```

正对角线是监督信号，批内其他配对充当负例。该目标直接优化图文配对辨别，不直接监督对象计数、空间关系或复杂逻辑。网页文本可能漏掉细节，批内“负例”也可能语义相关，因此检索中的“看起来接近”不等于严格满足查询。

这解释了本项目的实验动机，但不能仅凭一个失败案例证明训练机制导致该错误。机制推断需要额外数据与受控干预。原始方法来源：[Radford et al., 2021](https://proceedings.mlr.press/v139/radford21a.html)。

## 2. 归一化、温度与排序

L2 归一化后，点积等于余弦相似度。若不归一化，向量模长会引入与语义方向不同的因素。对于同一查询，只要温度为正，对全部候选统一缩放不会改变排序。

softmax 还依赖候选集：增删候选就会改变数值。因此 UI 展示原始 cosine，而不把它乘 100 后标为“置信度”。需要可靠概率时，应在目标任务的独立验证集上研究校准，并明确事件定义，不能直接解释 CLIP logits。

## 3. 模板集成的实现细节

对于模板 t₁…tₘ，先分别编码并归一化，再求平均，最后重新归一化：

```math
q = \operatorname{norm}\left(\frac{1}{m}\sum_{j=1}^{m}\operatorname{norm}(g(t_j(x)))\right).
```

本项目固定使用 `{}`、`an image of {}`、`a photo of {}`。这是检索查询上的简单消融，不是完整复现原论文的分类模板集。照片前缀可能与合成图不匹配，给已经是完整句子的查询再加前缀也可能不自然；所以不预设效果方向。

实现选择在 `encoder.py` 中可审计：`model.eval()`、`torch.inference_mode()`、FP32、先逐模板归一化。OpenAI checkpoint 使用 QuickGELU；与普通 GELU 混用可能改变输出，因此激活配置也进入索引指纹。具体接口来源：[OpenCLIP 官方仓库](https://github.com/mlfoundations/open_clip)。

## 4. 图文混合查询与 MMR

混合查询 q = norm((1−α)u_image + αv_text) 是表示空间中的插值启发式。它不是执行图像编辑，也不保证“原图加文字属性”具有可加组合语义。UI 允许对照不同 α；本轮研究协议没有把 α 搜索作为评测结论。

MMR 在最多 5K 个高分候选中迭代选择：

```math
\operatorname*{argmax}_{d\notin A}\big[(1-\lambda)\,s(q,d)-\lambda\max_{a\in A}s(d,a)\big].
```

首个候选保持原始第一名。λ 越大，对已选结果的冗余惩罚越大。图像相似不一定意味着语义重复，MMR 可能牺牲严格相关性。正式模板消融将 diversity 固定为 0；对比界面也强制如此。

## 5. 指标为什么要分开

| 指标 | 本项目定义 | 回答的问题 |
|---|---|---|
| Hit@K | 前 K 中至少一个相关项为 1，否则 0 | 能否快速找到任意正确结果？ |
| Recall@10 | 前 10 中相关项数 / 全部相关项数 | 正确结果找全了多少？ |
| MRR | 第一个相关结果的排名倒数，全图库排序 | 第一个正确结果有多靠前？ |
| AP@10 | 前 10 各相关位置的 precision 之和 / min(相关项总数,10) | 正确结果整体排序如何？ |
| mAP@10 | 查询 AP@10 的均值 | 多查询平均排序表现 |
| nDCG@10 | 二值相关性折损累计增益 / 理想排序增益 | 排序前部的相关性质量 |

单正例条件下，Hit@K 与 Recall@K 相等；多正例条件下不同，不能混称。许多文献使用另一种 AP@K 分母，本项目显式固定定义。若候选少于 10，截断到候选数量。相同分数按图像 ID 的稳定顺序打破平局，避免遍历顺序漂移。

## 6. 不确定性和数据泄漏

将同一幅图的多个改写当作独立样本会夸大有效样本数。本合成集进一步按颜色—形状分组，每组包含左右、数量变化和改写。每次 bootstrap 有放回抽取组，保留组内所有查询；计算 2000 次重采样均值的 2.5% 与 97.5% 分位数。

比较两个方法时，对齐相同查询，先求每条查询的指标差，再按相同组重采样。不是分别取两个均值区间再相减。只有 6 个测试组时，该区间仍很粗；它不是显著性检验的万能替代，也没有处理所有多重比较问题。主指标预先指定为 nDCG@10。

开发与测试查询组分离，图库固定。图库里有测试查询对应的图片是检索任务所需；本项目没有使用测试标签训练模型。禁止根据测试结果选择模板。真实数据还需检查近重复图、同一来源事件或同一对象系列的跨组泄漏，当前字节哈希去重只能发现完全相同文件。

## 7. 表示与工程正确性

索引保存权重内容摘要、OpenCLIP 版本、预处理与激活配置。查询编码器必须匹配指纹，否则启动失败。图像内容变化也会在启动时被检测。索引在临时 SQLite 文件中完整构建后原子替换，失败不会破坏旧快照。

精确检索成本约 O(Nd)，本项目避免 ANN 召回误差对模型比较的干扰。20,000 × 512 个 float32 向量约 39 MiB，但模型权重、中间激活和 JSON 元数据还会额外占用内存。规模更大时应在独立实验中比较 ANN 的召回、延迟和内存，而不是只给出单一吞吐数字。

推理锁避免同时操作同一模型；单 worker 避免每个进程重复加载权重。缓存索引存在于内存中，重建后需要重启服务。正式延迟不包含模型加载和图像建索引；复制到 CPU 的向量已同步后端工作。没有测量多用户并发吞吐或冷启动时间。

## 8. 本轮结论的适用边界

英语、合成几何图、小图库、单检查点与 CPU。未验证真实照片、中文查询、跨域、鲁棒性攻击、公平性或大规模部署。计数/空间错误值得进一步研究，但也可能受到合成域、颜色表现、模板及图像预处理影响，不能把所有差异归结为单一机制。

后续优先级：先补充有许可的自然图片与更丰富的关系难例；再固定协议比较检查点；最后才考虑训练轻量适配器。在获得独立测试证据前，不把“增加复杂度”视为提升。
